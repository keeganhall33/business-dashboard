# V4 De-Legacy Audit — 2026-08-31

## Objective
Protect useful-V1 delivery speed after the OpenClaw/V4 cutover. V4 is the sole active orchestration runtime. V3 is retained only as rollback evidence/fallback until sustained V4 production proof is complete.

## Decision rule
- **KEEP**: canonical, active, and useful for V1.
- **UPGRADE**: canonical but has a bounded defect or capacity limitation.
- **REBUILD**: repeated failures, duplicate truth, or maintenance cost exceeds clean replacement cost.
- **ARCHIVE**: retain for rollback/history but remove from active runtime/CI/product surfaces.
- **DELETE-DEFERRED**: obsolete and safe to delete after V1, but deletion provides no immediate throughput benefit.

## Immediate rebuild/cleanup priority
1. **Elastic V4 slot capacity + utilization proof** — remove one-stream/one-worker serialization and prove useful parallel execution.
2. **Independent first-party telemetry plane** — #891 FunnelKit and #892 Woo/website, with freshness/coverage and failure isolation.
3. **Evidence-honest executive state** — remove canned/shadow recommendations from dashboard overview/local artifact paths.
4. **Explicit V4 retry/attempt contract** — terminal history immutable, retries first-class, no label resurrection hacks.
5. **Canonical agent operating model** — one role/capability definition shared by runtime/UI; retire dead idea-quota machinery where unused.

## V1 scope guard
Useful V1 means reliable source freshness, aligned date ranges, checkout/funnel diagnosis, Meta→GA4→FunnelKit→Woo reconciliation, evidence/confidence, prioritized recommendations, and a usable executive surface. Broad schema archaeology, historical script deletion, and aesthetic cleanup do not block V1 and must not steal capacity.

## Active architecture
- **Production orchestration:** V4 only.
- **Authoritative task/runtime state:** local V4 SQLite.
- **GitHub labels:** synchronization/mirror only, not liveness authority.
- **Task execution:** disposable task workspaces from immutable canonical base.
- **Model:** local Ollama production path unless explicitly changed by approved architecture.
- **Integration/release:** separate bounded executor path.
- **V3:** rollback evidence/fallback only; no automatic CI/runtime execution.

## Exit gate for legacy retirement
Delete V3 runtime assets only after V4 has sustained production operation with parallel product work, successful retry/recovery behavior, and no fallback invocation needed. Until then, archive rather than delete.
