# Autonomous Growth Operational Proof V1

## Purpose

`AutonomousGrowthCanaryV1` is the fail-closed acceptance gate for the production learning loop in #1695. It does not create decisions, campaigns, relationships, allocations, outcomes, attribution, learning, or policy. It only evaluates explicit evidence produced by the existing canonical systems.

A green unit test or fixture is not production proof. The canary can return `CERTIFIED_PRODUCTION_LOOP` only for `PRODUCTION` evidence with an exact canonical subject and lineage covering every required stage.

## Required production stages

The same governed lineage must explicitly prove event ingestion, investigation, counterfactual scenario review, constrained allocation, relationship path, deal-structure preparation, approval gate, action or experiment, outcome measurement, attribution classification, learning update, reallocation review, chief-of-staff synthesis, scheduler/runtime activation, and production telemetry.

Historical business stages may be older because a real opportunity or campaign can unfold over time. Scheduler/runtime and production-telemetry evidence must remain current within the bounded freshness window.

## Guardrails

- Fixture and shadow evidence cannot certify a production loop.
- Missing, blocked, future-dated, or lineage-mismatched evidence fails closed.
- Attribution is preserved exactly as observed. `NOT_ESTABLISHED` and `CORRELATIONAL` are valid explicit classifications and are never upgraded to causal.
- Telemetry is observational only. Missing values remain `null`; they are never silently converted to zero.
- If an external action actually executed, explicit approval evidence is required.
- A policy promotion can certify only when shadow-test, rollback, and approval evidence are all explicit. The canary itself cannot promote policy.
- No confidence, monetary value, deal probability, outcome direction, or causal effect is generated by this contract.
- The canary grants no spend, outreach, contract, allocation-mutation, policy-promotion, external-action, or approval-bypass authority.

## Live acceptance

The production milestone remains incomplete until one real canonical opportunity or campaign supplies the required evidence through the deployed loaders/runtime and the canary certifies it without manual context transfer. The acceptance artifact should retain the canary run ID, canonical subject ID, exact lineage ID, stage evidence references, explicit attribution class, observed telemetry, and any policy-change safety evidence.
